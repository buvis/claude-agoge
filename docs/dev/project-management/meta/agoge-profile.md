Not checked: `head` keys/types, `untracked` element types, `untracked_fingerprints` value types, `dirty`/`gitdir` value types, and every field of nested `submodules` snapshots (nested refs still skip the malformed-ref check). Each falls through to the generic `except Exception` exit 2 or to a silent mis-compare.
- Submodule recursion still has no depth bound (`take_snapshot`, `_filter_overrides`).
- `_fingerprint` is `lstat` then `open()` without `O_NOFOLLOW`/`O_NONBLOCK`: a regular file swapped for a fifo between the two calls can still block. Only `PermissionError` is turned into a named reason; other `OSError`s go to the generic exit 2.
- Overflow mode (`> 20000` ignored files, `IGNORED_FILE_CAP`): keeps only `--directory` entries ending in `/`, so an ignored file matched by a file pattern (e.g. top-level `x.log`) drops out entirely and its removal is unchecked; the cap is decided on `before` OR `after`, so crossing the cap during a run silently downgrades the check. Documented in the docstring and CHANGELOG.
- Sampling (`SAMPLE_ABOVE` 64 MiB): same-size middle edits undetected, documented. Applies to dirty tracked, untracked and git-dir files alike.
- `_is_symlink_escaping` is an `lru_cache` cleared at the start of each `take_snapshot`; the recursive submodule call clears it mid-parent-snapshot (correctness looks fine, cost only).
- Filter discovery still trusts `git config --includes --get-regexp` to see every source status sees (conditional includes, `GIT_CONFIG_GLOBAL`/`SYSTEM`).
- Allocator: `backlog.mkdir(parents=True)` runs before the `O_NOFOLLOW` open and realpath check, so a symlinked ancestor swapped in after `main()`'s check can still make mkdir create directories outside the repo (no file is written there).

## Mocking strategy

No external service is called by the code, so nothing needs a mock for the probes above. Not reachable or not run:
- `/run-agoge` itself (needs a live Claude Code session and subagent dispatch): do not simulate. Report full-pipeline claims as `unverified`.
- `dev/bin/release` (needs `../claude-plugins`, pulls, tags, pushes): do not run. Claims about it are `unverified`, not `mocked`.
- CI on the new code: no run exists and lanes must not push or dispatch one. Claims about ubuntu or Python 3.12 behaviour are `unverified`. A lane may emulate 3.12 with `uv run --python 3.12 ...` in scratch and report that `mocked`.
- Non-UTF-8 file names and refnames: APFS rejects them. Emulate only with git objects/refs built in a scratch repo (`git update-index --cacheinfo` with a raw byte path, `git update-ref` with a raw byte name), and report `mocked`, not `verified`.
- Files owned by another user: cannot be created without root. Use mode 000 as the stand-in and report owner-based cases as `mocked`.
- Race windows (fifo swap, allocator ancestor swap): driven by a scratch swapper loop; a race not won in N tries is `unverified`, not disproved.
