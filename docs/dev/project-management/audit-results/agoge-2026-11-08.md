### 1 of 18 - HIGH - Parallel PRD claims with different slugs get the same number

**What.** `allocate_prd_number.py` hands two callers the same PRD number when they run at once with different slugs. It lives in `skills/run-agoge/scripts/allocate_prd_number.py`. Walter found it.

**Evidence.** 16 callers started together with slugs `s0..s15`, 10 trials: every trial had duplicates, for example `{'00001': 5, '00006': 2, '00003': 3}`. Two callers (`alpha`, `beta`) collided in 19 of 20 trials. Same-slug callers stayed distinct in 10 of 10. Confidence: confirmed.

**If unchanged.** The allocator exists to stop two writers taking one number. `O_EXCL` guards the full file name, not the number, so it only works when the slugs match. Two emitters (a walkthrough and a loop) will file two PRDs with one number. Likely whenever writers overlap; stable, does not compound.

**Options.**
1. **Claim the number, not the name.** Create an exclusive `backlog/.NNNNN.claim` marker with `O_EXCL`, then the real file. Benefit: closes the race for any slug. Drawback: a leftover marker file per number. Effort S. Risk: a crash leaves a stale marker that skips a number (harmless).
2. **Re-scan after create.** After creating the file, re-scan; if another file holds the number, remove yours and try the next. Benefit: no new files. Drawback: a window remains between two re-scans. Effort S. Risk: two callers can both back off and retry forever without jitter.
3. **Lock around scan and create** (`fcntl.flock` on a lock file). Benefit: simplest correct model. Drawback: POSIX-only (fine here). Effort S. Risk: a lock file in the backlog dir.
4. Accept or defer.

**Recommendation: option 1**, with a parallel regression test (N processes behind a barrier, distinct slugs, assert N distinct numbers). Against it: one more hidden file per PRD in the backlog dir.

### 2 of 18 - HIGH - A lane can install a git hook in the target and the integrity check still says unchanged

**What.** The snapshot records HEAD, refs, index, tracked files, worktrees and local config, but not `.git/hooks/`, `.git/info/exclude` or `.git/info/attributes`. It lives in `skills/run-agoge/scripts/target_snapshot.py`. Heidi found it.

**Evidence.** Wrote an executable `.git/hooks/pre-commit`, then `compare` → `rc=0 unchanged [] touched= []`. Same for `.git/info/exclude` (+`lane-junk/`) and `.git/info/attributes` (`* filter=evil`). Confidence: confirmed.

**If unchanged.** The integrity gate is the pack's promise that a run left the repo as it found it. A lane that plants a hook gets code run on the operator's next commit, and the report says "unchanged". Rare (lanes are pinned read-and-run), but silent and lasting.

**Options.**
1. **Hash `hooks/*`, `info/*` and `config.worktree`** (paths from `git rev-parse --git-path`) into the snapshot, new kind `gitdir`. Benefit: closes the named gaps. Drawback: other `.git` files stay unchecked. Effort S. Risk: snapshot format bump breaks old snapshot files (they exit 2, which is fine).
2. **Hash every file under `.git` except objects, logs and index**. Benefit: covers the class. Drawback: git's own housekeeping (`FETCH_HEAD`, `ORIG_HEAD`, `gc.log`) causes false alarms. Effort M. Risk: noisy failures.
3. Option 1 now, plus a test listing the `.git` entries deliberately ignored, so a new one forces a decision. Effort S-M.
4. Accept or defer.

**Recommendation: option 3.** Against it: the ignore list needs upkeep as git adds files.
