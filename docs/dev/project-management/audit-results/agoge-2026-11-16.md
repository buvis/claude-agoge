## 1 of 11 - MEDIUM - `compare` runs the target's `gpg.program` when a ref changes

**What.** When a ref changes, `compare` runs `git log -1` and `git reflog show` under the repo's own config. If that config sets `log.showSignature=true` and `gpg.program`, git runs the program. Lives in `_ref_violation` in `target_snapshot.py`. Found by trudy. The docstring's out-of-scope list does not name gpg, so it is a gap, not a documented limit.
**Evidence.** Confirmed. Scratch repo with `gpg.program=<marker script>`, `log.showSignature=true`; after `snapshot`, branch `refs/heads/evilref` was added at a commit with a fake `gpgsig` header. `target_snapshot.py compare` exited 1 with a ref violation and the marker file gained `gpgprog` twice. Plain `git log -1 --format=%an <sha>` fired it too.
**If unchanged.** A hostile repo can run a program of its choice when a lane (or the run) creates a ref. Likely only on a hostile target. Stable, does not compound. Hit: the operator's machine.
**Options.**
1. Patch (S): add `log.showSignature=false` and `gpg.program`, `gpg.ssh.program`, `gpg.x509.program` set to `false` to `_STATIC_OVERRIDES`. Good: one line each. Bad: lists names, so the next signing hook is missed. Ugly: none known. Risk: signed-commit output changes (not used here).
2. Root fix (S): pass `--no-show-signature` and stop using `git log` for the author field; use `git cat-file -p`. Good: no config reaches the call. Bad: parse commit text. Risk: author format drift (guess).
3. Prevent the class (M): run every git call with an empty config except an allow-list. Good: closes all vectors. Bad: breaks discovery of the filter drivers it must disable. Ugly: big change to a hardened file.
4. Defer.
**Recommendation.** Option 1, plus a docstring line and a regression test. Against: it is a deny-list.

## 2 of 11 - MEDIUM - A fifo or `/dev/zero` symlink under `.git` hangs the snapshot; a large git-dir file is read whole

**What.** `_gitdir_files` opens and reads every file under the git dir with no type, symlink or size check. Lives in `target_snapshot.py`. Found by trudy (hang) and peggy (memory). **Already queued: PRD 00025.**
**Evidence.** Confirmed. `.git/hooks/ff` as a fifo: `timeout 5 python3 -I target_snapshot.py snapshot <repo> <out>` rc=124 after 5.0s. Symlink to `/dev/zero`: rc=124 at 1.2s. 1 GiB sparse `hooks/pre-commit`: peak RSS 1,049 MiB (1,053 MiB at c7da90f).
**If unchanged.** A hostile repo freezes or exhausts the run before any lane starts. Stable.
**Options.** (1) Use `_fingerprint` for the git dir, as PRD 00025 says (S). (2) Skip the hooks dir content (S; loses hook-change detection). (3) Add a per-call timeout only (S; hides the memory case).
**Recommendation.** Option 1, already in the backlog. Against: it changes every git-dir fingerprint, so old snapshots stop comparing (version is already 4).

## 3 of 11 - MEDIUM - Untracked files are hashed in full; snapshot gets 4-16x slower

**What.** `_fingerprint` hashes every untracked file. Found by peggy. **Already queued: PRDs 00024 and 00026.**
**Evidence.** Confirmed. 100k untracked: snapshot 3.62s, compare 3.65s (old 0.23s); `before.json` 12.36 MB (old 2.78 MB); compare peak RSS 126 MiB. 2 x 2 GiB sparse: 1.77s (old 0.13s). Warm, reproduced twice. No budget stated, so observation-only.
**If unchanged.** Every run pays this three times on the target; a repo with a dataset costs minutes. Grows with repo content.
**Options.** (1) Fingerprint by size, mtime and a head/tail sample (S, weaker detection). (2) Keep full hash, cap by size and record `big:<size>` above it (S). (3) Cache hashes by (size, mtime_ns) between snapshot and compare (M).
**Recommendation.** Per PRDs 00024/00026. Against: any shortcut can miss a same-size edit.

## 4 of 11 - MEDIUM - `chmod` on an untracked file is not reported

**What.** `_fingerprint` hashes content only, so a mode change shows as unchanged. Found by walter. **Already queued: PRD 00030.**
**Evidence.** Confirmed. Untracked `u.txt` at 644, `chmod 755 u.txt`, `compare`: `status=unchanged violations=[]`, rc=0. Doubt: git itself ignores modes of untracked files, so this is a product choice. Walter's profile row expected `untracked-modified`.
**If unchanged.** A run could make a file executable and the check would pass. Low chance. Stable.
**Options.** (1) Add the permission bits to the fingerprint (S). (2) Add only the exec bit (S). (3) Document it as not checked (S).
**Recommendation.** Option 1. Against: some filesystems change modes on their own.

## 5 of 11 - MEDIUM - `--allow ign` does not exempt a removed ignored directory

**What.** The directory is recorded as `ign/` plus every child, and `--allow` matches the exact string. Found by walter. **Already queued: PRD 00027.**
**Evidence.** Confirmed. Removed `ign/` with `f` and `sub/g`; `--allow ign` gives rc=1 (`ign/`, `ign/f`, `ign/sub/g`); `--allow ign/ --allow ign/f --allow ign/sub/g` gives rc=0.
**If unchanged.** An operator who allows a directory still sees violations and may stop trusting the check. Stable.
**Options.** (1) Make an allowed path cover its `/` form and every child (S). (2) Document that each child needs its own `--allow` (S). (3) Add a `--allow-dir` flag (M).
**Recommendation.** Option 1. Against: a wider match can hide more than meant.

## 6 of 11 - LOW - The PRD allocator's containment check can be raced

**What.** `main` checks the backlog path, then `claim()` writes through the path again, so a swapped symlink sends the file outside the repo while the printed path stays inside. Lives in `allocate_prd_number.py`. Found by trudy. **New.**
**Evidence.** Confirmed. With a 60000-file `discovery/` to widen the window, a thread swapped `prds/backlog` for a symlink while the flock was held. `allocate_prd_number.py <repo> probe` exited 0 and printed `.../prds/backlog/60000-probe-v1.md`; the file was in the outside directory. Needs an attacker who can write to the repo during the run.
**If unchanged.** Very unlikely: the attacker needs write access to the operator's repo at the moment of the run. Stable.
**Options.** (1) Open `prds/backlog` once with `O_DIRECTORY|O_NOFOLLOW` and create the file with `dir_fd` (M). (2) Re-check containment after the create and unlink on failure (S; leaves the window). (3) Accept and document (S).
**Recommendation.** Option 3 for now, option 1 if the allocator ever runs on untrusted repos. Against: an unattended loop can point it at one.
