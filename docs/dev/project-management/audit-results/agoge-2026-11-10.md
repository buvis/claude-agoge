### 1 of 22. HIGH. Snapshot hangs or eats unbounded memory on a fifo, a `/dev/zero` link or a large file inside `.git`

**What.** `_gitdir_files` opens and reads every file under the git dir whole, with no type check. A fifo blocks it forever; a symlink is followed; a big file is held in memory entirely. Trudy found the hang and the link-following; peggy measured the memory.

**Evidence.** `.git/hooks/fifo-hook` fifo -> `rc=137 elapsed=8s` (killed). `.git/info/zero -> /dev/zero` -> `maxrss 12527 MB` after 2 s. 4 GiB sparse `.git/lfs` object -> `4333748224 maximum resident set size` (`/usr/bin/time -l`), same on c7da90f. Confirmed.

**If unchanged.** A repo with a multi-GB LFS object swaps or OOMs four times per agoge run; a stray fifo stops the run at step 1 with no message. Already reported 2026-11-09; stable, not compounding.

**Options.**
- **A. `lstat` each entry; hash link text for symlinks, `special:<mode>` for non-regular files, chunked reads for regular ones (recommended).** Benefit: one change closes hang, link-follow and memory, mirroring `_fingerprint`. Drawback: snapshot shape changes. Effort S. Could break: needs a `VERSION` bump to 5.
- **B. Skip `lfs/` and non-regular files.** Benefit: smaller. Drawback: a planted fifo or LFS change goes unreported. Effort S.
- **C. Accept or defer.** Drawback: second report of the same defect.

**Recommendation: A.** Against it: another format bump invalidates in-flight snapshots (harmless between runs, but bundle with finding 9 if both land).

### 2 of 22. HIGH. `compare` runs the target's `gpg.program` when a ref has moved

**What.** When a ref moved, `_ref_violation` runs `git log` and `git reflog show` on it. With `log.showSignature=true` in the target, git calls `gpg.program` on a signed commit. Trudy found it.

**Evidence.** `log.showSignature=true`, `gpg.program=<marker.sh>`, ref moved to a commit with a `gpgsig` header, `compare` -> rc 1 and 4 marker lines (`ran: .../marker.sh --keyid-format=long --status-fd=1 --verify ...`). Fresh snapshot: 0 hits. Confirmed.

**If unchanged.** A target repo runs a program of its choice inside the master's integrity check, exactly when a ref moved. Low odds on own repos; it defeats the "does not run repo programs" goal of PRD 00010.

**Options.**
- **A. Pass `--no-show-signature` to both calls and add `log.showSignature=false` to `_STATIC_OVERRIDES` (recommended).** Benefit: two-line fix, closes the vector. Drawback: none known. Effort S. Could break: nothing likely.
- **B. Drop the `log`/`reflog` lookup and report the ref oid only.** Benefit: removes the whole call class. Drawback: loses commit author/subject from reports. Effort S.
- **C. Accept or defer.**

**Recommendation: A.** Against it: other `log.*`-style config may still reach programs; a sweep test of git's config docs is needed to be sure.

### 3 of 22. HIGH. A plain `git status` in a filtered repo makes compare fail the run though nothing changed

**What.** With filters disabled, whether a filtered file counts as dirty depends on git's index stat cache, not on content. Any read-only `git status` (a lane, an editor) refreshes that cache and flips the result. Heidi found it.

**Evidence.** CRLF file under `filter.crlf.clean = tr -d '\r'`, mtime moved back. `snapshot` -> `dirty: {'a.txt': ' M ...'}`; plain `git status`; `compare` -> rc 1, `{"kind": "tracked", "path": "a.txt", "before": " M ...", "after": null}`. Reverse (mtime-only touch) fails too. No step between -> rc 0. Confirmed.

**If unchanged.** Any repo with a normalizing or LFS filter can fail a run with a false violation, and the report tells the operator to restore something that never changed. Likely on LFS repos; stable.

**Options.**
- **A. For paths with a `filter` attribute, record a worktree content fingerprint and drop them from status-derived `dirty` (recommended).** Benefit: stat-independent. Drawback: hashes those files each snapshot (adds to finding 4). Effort M. Could break: format bump.
- **B. Run `git update-index --refresh` (filters off) before every status.** Benefit: small. Drawback: writes the target's index, which the check itself forbids. Effort S.
- **C. Accept or defer.**

**Recommendation: A.** Against it: costlier on large LFS worktrees.

### 4 of 22. HIGH. Every snapshot reads and hashes every untracked byte

**What.** `_fingerprint` hashes the full content of each untracked file on every snapshot and compare (four per run). Cost is linear in untracked bytes and count. Peggy measured it; trudy hit the extreme.

**Evidence.** 100k untracked files: snapshot 3.63 s, 60.9 G instructions vs 0.23 s / 0.95 G on c7da90f (`/usr/bin/time -l`). 4 GiB untracked file: 4,294,994,324 bytes read vs 27,028. 1 TiB sparse untracked file: `rc=137 elapsed=30s`. Confirmed.

**If unchanged.** Repos with build outputs or datasets not gitignored take tens of seconds to minutes per run, or stall. Grows with the repo.

**Options.**
- **A. Compare `(size, mtime_ns, ino, mode)` from `lstat` first; hash only on mismatch (recommended).** Benefit: near-old speed, also catches finding 9 (mode). Drawback: a same-size same-mtime overwrite is missed. Effort S. Could break: format bump.
- **B. Hash only up to a size cap, then `size+mtime`.** Benefit: bounds the worst case. Drawback: still reads 100k small files. Effort S.
- **C. Accept or defer.**

**Recommendation: A.** Against it: mtime can be forged by a hostile lane; this trades exactness for speed.
