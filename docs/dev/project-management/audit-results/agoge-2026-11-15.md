## 1 of 14 — HIGH — Snapshot and compare cost grows linearly with untracked files, 25x-40x slower than c7da90f

**What.** Every untracked file is now opened, hashed and stat'ed several times. It lives in `target_snapshot.py` (`_fingerprint`, `_external_symlink_ancestor`). Found by peggy. Each agoge run takes at least three snapshots.

**Evidence** (confirmed, no budget stated, so observation-only). 100k untracked files: snapshot 4.0-9.1 s, compare 3.6-7.8 s, against 0.24-0.30 s at c7da90f. 10k files: 0.45 s against 0.12-0.16 s. `before.json` 13.2 MB against 3.2 MB. cProfile of the 100k snapshot: `_fingerprint` 9.74 of 10.9 s, with 400k `lstat` calls (four per file, from a per-path-component symlink walk). The 15 git calls total 0.73 s.

**If unchanged.** A target with a big untracked tree (build output outside .gitignore, vendored data) adds tens of seconds per run. Stable per run, grows with the target.

**Options.**
1. Patch: memoise the symlink-ancestor walk per directory and take the fingerprint from one `lstat`. Benefit: removes about 75% of syscalls. Drawback: still hashes every byte. Effort S. Could break: symlink-escape detection if the cache goes stale (guess).
2. Root fix: option 1 plus a size cap (see packet 3) so large files are not fully hashed. Benefit: cost bounded by file count. Drawback: weaker detection for big files. Effort M.
3. Accept or defer: cost is seconds, not minutes, at typical sizes.

**Recommendation: 1.** Strongest reason against: no budget exists, so "slow" is a judgement.

## 3 of 14 — MEDIUM — Untracked files are hashed in full, so cost grows with bytes

**What.** `_fingerprint` hashes every byte of every untracked or dirty regular file. In `target_snapshot.py`. Found by peggy and trudy.

**Evidence** (confirmed). Sparse untracked file: 1 GiB snapshot 2.26 s (c7da90f 0.72 s); 4 GiB 5.00 s (0.79 s); a 50 GiB sparse file took 22.4 s (trudy). About 1.1-1.2 s per GiB for zeros; real data adds disk IO. Memory stays 30 MB. Ignored files are never read.

**If unchanged.** A multi-GB untracked file (dataset, VM image) costs minutes over the three snapshots per run.

**Options.**
1. Patch: above a size threshold, fingerprint `size:mtime_ns` only. Effort S. Could break: a same-size, same-mtime edit goes unseen (guess: rare).
2. Root fix: hash first and last MiB plus size above the cap. Effort S-M.
3. Accept or defer.

**Recommendation: 2.** Strongest reason against: any sampling weakens the "never changed the target" guarantee.

## 5 of 14 — MEDIUM — `--allow` on a removed directory does not exempt its contents

**What.** `--allow` matches paths exactly. Removing an ignored or untracked directory yields one violation per entry. In `target_snapshot.py` (`compare`). Found by walter.

**Evidence** (confirmed). Ignored `igndir/` with `f` and `sub/g`, then `rm -r igndir`. `--allow igndir` gave exit 1 (three violations). `--allow igndir/` gave exit 1 (`igndir/f`, `igndir/sub/g` left). Only all three paths together gave exit 0. An empty removed ignored dir needs the trailing slash.

**If unchanged.** A user cannot exempt a deliberately removed directory without listing every file. Stable.

**Options.** 1. Treat an `--allow` path as a prefix for children (S; could over-allow). 2. Prefix match plus a usage line documenting the rule (S). 3. Document the exact-match rule only (S).

**Recommendation: 2.** Strongest reason against: prefix matching widens what one flag exempts.
